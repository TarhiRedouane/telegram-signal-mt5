## Acceptance Criteria

**Functional Requirements:**
1. New doc `docs/architecture/review-2026-10.md` exists with these sections: current structure, findings, target structure, refactor plan.
2. **Current structure:** per file over 600 lines, a table of its responsibilities (one row per concern, with method names for `main.py`) and who calls it. `main.py` rows cover all 42 methods.
3. **Findings**, each with evidence (file:line or grep result), severity, and an action (delete / simplify / keep with reason):
   - dead code: functions/classes with no caller outside tests;
   - duplicated logic (same rule in two places, e.g. sizing, price normalisation, setup handling);
   - the 4 suspected unused dependencies, each confirmed by grep for imports in `src/ main.py cli.py scripts/ tests/`;
   - the 4 bypassed modules: used, partly used, or dead; if dead, say what replaced them;
   - drift from `docs/architecture/*` (list only; fixing the docs is a separate follow-up).
4. **Target structure:** a proposed file layout that splits `main.py` into at least: app wiring/lifecycle, message router, setup/zone orchestration (ladder, legs, invalidation), order execution (sizing + risk guard + MT5). Each target file lists the `main.py` methods it receives and its approximate size. `main.py` ends as wiring only.
5. **Refactor plan:** ordered list of stories (19.2 characterization tests, 19.3+ one extraction each, last story = delete dead code/deps). Each entry: scope, files touched, which untested paths it needs covered first, risk (low/med/high), rollback.
6. Plan respects the order of work in the roadmap: the split must leave clear seams for step 18 (`settings.get_telegram_groups()`, `main._poll_telegram_groups`) and step 3 (what it touches in `main.py`).

**Integration Requirements:**
7. No change to any `.py`, `requirements.txt`, `pyproject.toml` or `config/` file. `git diff --stat` shows only `docs/`.
8. Existing behaviour untouched: complete single-message signals and multi-message setups keep working (nothing to run, guaranteed by AC7).

**Quality Requirements:**
9. Every finding is checkable: a reviewer can reproduce it with the given grep/command. No "feels messy" findings.
10. Roadmap step 19: tick "Review" and "Target structure" boxes, and link the doc. Leave the other two boxes open.
11. Dev Agent Record lists the commands used for the evidence (import greps, caller greps, coverage run if any).
