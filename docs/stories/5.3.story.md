## Story
**As a** developer of the signal bot,
**I want** the whole codebase formatted by `black` once, in a commit that contains nothing else,
**so that** step 19 refactor diffs show only moved/changed code, and `black --check` can be trusted from now on.

## Story Context

**Existing System Integration:**
- Integrates with: every Python file in the repo; config in `pyproject.toml` (`[tool.black]`, line length 100,
  `py312`, excludes `.eggs .git .venv build dist`)
- Technology: black 24.10.0 (pinned in `requirements.txt` / `pyproject.toml`, already installed in `.venv`)
- Follows pattern: `docs/architecture/coding-standards.md` ("black + ruff, line length 100")
- Touch points: formatting only. No logic change in any file.

**Baseline measured 2026-10-11:**
`.venv/Scripts/python.exe -m black --check src tests main.py cli.py config scripts` →
**91 files would be reformatted, 17 unchanged**. Includes `main.py`, `cli.py`, all of `src/` (Telegram, MT5,
risk, correlation), `config/`, `scripts/`, `tests/`. `CLAUDE.md` documents `black src/ tests/`, which misses
`main.py`, `cli.py`, `config/`, `scripts/`.

## Acceptance Criteria

**Functional Requirements:**
1. Precondition: story 5.2 is committed and `git status` is clean before formatting starts (so the formatting
   commit cannot pick up other changes).
2. `black .` run from the repo root with the `pyproject.toml` config; afterwards `black --check .` passes for the
   whole repo (0 files would be reformatted).
3. The formatting commit contains **only** black's output: no hand edits, no ruff `--fix`, no import sorting,
   no renames. black runs in its default safe mode (it checks the AST is unchanged); `--fast` is not used.
4. `git blame` stays useful: a second commit adds `.git-blame-ignore-revs` with the formatting commit's full SHA
   (GitHub uses this file automatically; locally `git config blame.ignoreRevsFile .git-blame-ignore-revs`).

**Integration Requirements:**
5. Full `pytest` gives the same result as before: **693 passed, 6 skipped**, 0 failed, 0 errors.
6. Complete single-message signals and multi-message setups unaffected: guaranteed by AC3 (no AST change) and
   AC5 (suite unchanged). No demo run needed for a formatting-only change.
7. `ruff check` total does not increase (black may remove some whitespace hits, e.g. W293; record before → after).

**Quality Requirements:**
8. `CLAUDE.md` lint command `black src/ tests/` → `black .`, in the second commit (with AC4), not in the
   formatting commit.
9. Dev Agent Record lists: files reformatted (count), pytest result, ruff before → after, both commit SHAs.

## Technical Notes
- **Integration approach:** one mechanical command; black is AST-safe by default, so behaviour cannot change.
  Tests are the second guard.
- **Why two commits:** the formatting commit's SHA is only known after it exists; and keeping `CLAUDE.md` /
  `.git-blame-ignore-revs` out of it keeps "formatting only" literally true.
- **Line endings:** the repo shows "LF will be replaced by CRLF" warnings (`core.autocrlf`); black keeps each
  file's existing line endings. If `git diff --stat` shows whole-file changes on files black did not report,
  stop and check `.gitattributes`/autocrlf before committing.
- **Key constraints:** no other changes in commit A (AC3); high-risk code rule is satisfied because no logic
  changes.
- **Out of scope:** pre-commit hook, CI check for black (roadmap step 5 optional CI box), ruff auto-fixes,
  mypy errors, import sorting.

## Risk and Compatibility Check
- **Primary risk:** a non-formatting change hidden in a 91-file diff.
- **Mitigation:** clean tree before (AC1), black safe mode (AC3), suite unchanged (AC5), docs in a separate commit.
- **Rollback:** `git revert` commit A (and B); nothing else depends on them.
