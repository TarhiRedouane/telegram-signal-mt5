## Acceptance Criteria

**Functional Requirements:**
1. `pytest tests/integration` (with the real `pytest.ini`, `-W error` live) completes in **< 1 minute**; no test hangs.
2. Integration suite is **green**: 0 failed, 0 errors, with `--maxfail` disabled. Skips allowed only for I4
   (3 tests, written reason pointing at step 19) or with a written reason recorded in the Dev Agent Record.
3. Full run `pytest` (unit + integration together) is green and completes in **< 2.5 minutes**; result is the same
   as each file run alone (order-independent, as in 5.1 AC3).
4. `pytest-cov` installed and pinned (I9); `pytest --cov=main --cov=src --cov-report=term` runs.
5. Coverage baseline recorded: total `src/` %, and `main.py` % plus the list of `main.py` methods with **0 %**
   coverage, written into `docs/roadmap.md` step 19 (input for the refactor stories).

**Integration Requirements:**
6. No `src/` changes. If a finding turns out to be a real production bug, stop, record it, and split it into its
   own story (escalation trigger below), unless it is a one-line fix in a non-trading path (monitoring) like 5.1 F10.
7. Unit suite stays green and unchanged in assertions (629 passed, 2 skipped).
8. Safety rules stay as they are: the time-based ambiguity refusal (I6), the LLM "no buy/sell word, no trade"
   guard, and risk guard behaviour are not touched to make a test pass.

**Quality Requirements:**
9. No blanket `xfail`, no deleted assertions to get green, no new `filterwarnings` ignore entries.
10. `ruff check` passes on touched test files with no new hits (black formatting is a separate roadmap item).
11. Dev Agent Record lists each I-row: fixed in test / skipped (reason) / escalated, with one-line reason.
12. `docs/roadmap.md`: step 5 gets a ticked box for the integration suite; step 19 gets the coverage baseline;
    `CLAUDE.md` test commands line `pytest --cov=src` stays valid.

## Technical Notes
- **Integration approach:** tests and test deps only. Every finding above was traced to a stale test, a test of
  unwired code (I4), or a missing dev dependency (I9).
- **Existing pattern reference:** 5.1 F1 (loop started as a task), F8 (patch where looked up), F9 (stale mocks
  vs current handler), `tests/conftest.py` `close_log_handlers()` for teardown.
- **Key constraints:**
  - High-risk code rule (`CLAUDE.md`): Telegram + MT5 paths get no changes in this story.
  - Integration tests must not reach real services: no real OpenAI, Telegram or MT5 calls (5.1 F8 found a test
    hitting the real OpenAI client). If a test does, patch it where the name is looked up.
  - `-W error` is live since 5.1: leaked tasks/unawaited coroutines must be fixed in the test, not ignored.
- **Why I4 is skipped, not fixed:** fixing `CloseProcessor` means changing code production never runs, and
  step 19 decides whether it stays. Skipping keeps the decision visible instead of paying for it twice.
- **Out of scope:** CI, `black` reformat, LLM rate limiter throttling (separate roadmap step 5 boxes),
  any coverage threshold, new tests for `main.py` (step 19 decides what to cover first using AC5's list).
