### Refactoring Performed
- **File**: `tests/conftest.py`
  - **Change**: autouse fixture `_no_real_llm_services`: replaces the real `openai_client._client` with a stub
    that raises on any use, and points the shared `llm_cache` at a per-test `tmp_path` database.
  - **Why**: the same "patched where defined, not where looked up" mistake happened twice (5.1 F8, 5.2 I10)
    and each time failed silently: real API calls (cost, outbound traffic) and fake answers written to the
    live cache. A test fixing only today's call sites does not stop the next one.
  - **How**: one guard for every importer (they all share the same objects). Full suite still green with it,
    so no other test reaches the real services; a future miss now fails loudly with the fix in the message.
- **File**: `tests/integration/test_correlation_flow.py` (`test_bulk_correlation_processing`)
  - **Change**: assertion `> 0` → all 10 correlated and `[r.id for r in results] == position_ids`; the bulk
    now goes through the reply chain (`get_messages` mocked to return each signal as root,
    `human_delay` mocked) instead of the spaced time-based setup.
  - **Why**: with the stricter assertion the dev's version failed 1/10. Cause: `time_matcher` loads candidate
    signals with `get_recent_signals(minutes=window+2)`, measured from **now** (`repository.py:337`), not
    from the message timestamp, so only the newest spaced signal is ever a candidate. 10 unambiguous
    simultaneous time-based matches are impossible by design (only a few symbols are recognised; same-symbol
    candidates are refused as ambiguous, which is correct).
  - **How**: the test now proves bulk correlation maps each follow-up to its own position, on the path
    production tries first; time-based matching stays covered by the other tests in the file. 0.3 s.
