### Project Structure
**Source:** [Source: architecture/source-tree.md]
The project follows a modular structure with clear separation of concerns:
- **Main source:** `src/` directory with modular packages
- **Configuration:** `config/` for settings management with pydantic
- **Testing:** `tests/unit/`, `tests/integration/`, `tests/fixtures/`
- **Utilities:** `scripts/` for utility scripts, `logs/` for log files (gitignored)
- **Data:** `data/` for SQLite database and session files (gitignored)
- **Entry points:** `main.py` (application), `cli.py` (CLI commands)

### Technology Stack Requirements
**Source:** [Source: architecture/tech-stack.md]
**Critical Dependencies:**
- **Python 3.12.7** (LTS version, stable, excellent asyncio support)
- **Telethon 1.40.0** (User session support, mature, well-documented)
- **python-dotenv 1.0.1** (Environment management, secure credential handling)
- **aiofiles** (Async file operations)
- **SQLAlchemy 2.0.43** (Latest 2.0 series, async support, migration management)
- **aiosqlite 0.20.0** (Non-blocking database access)

**Development Dependencies:**
- **pytest 8.4.1 + pytest-asyncio 0.25.0** (Testing framework with async support)
- **mypy 1.13.0** (Static type analysis)
- **black 24.10.0** (Code formatting, line length 100)
- **ruff 0.8.4** (Fast linting, replaces flake8/pylint)

### Configuration Management
**Source:** [Source: architecture/source-tree.md#config]
- **Settings location:** `config/settings.py` with pydantic for validation
- **Logging config:** `config/logging_config.py` with rotating file handlers
- **Environment variables:** Use python-dotenv for secure credential loading

### Required Environment Variables
**Source:** [Source: architecture/tech-stack.md, architecture/source-tree.md]
Minimum required in .env.example:
```
TELEGRAM_API_ID=your_api_id_here
TELEGRAM_API_HASH=your_api_hash_here
PHONE_NUMBER=your_phone_number
```

### Git Security Requirements
**Source:** [Source: architecture/coding-standards.md#critical-rules]
Must exclude from git:
- `.env` files (contain secrets)
- `*.session` files (Telegram session data)
- `logs/` directory
- `data/` directory (database files)
- `__pycache__/` and `.pytest_cache/`

### File Locations for New Code
**Source:** [Source: architecture/source-tree.md]
- **Main entry:** `main.py` (application entry point)
- **CLI entry:** `cli.py` (CLI commands: start, stop, status)
- **Configuration:** `config/settings.py`, `config/logging_config.py`
- **Dependencies:** `requirements.txt`, `pyproject.toml`
- **Testing config:** `pytest.ini`, `.ruff.toml`, `mypy.ini`

## Testing

### Testing Standards
**Source:** [Source: architecture/test-strategy-and-standards.md]
- **Framework:** pytest 8.4.1 with pytest-asyncio 0.25.0
- **File Convention:** `test_{module_name}.py`
- **Unit Test Location:** `tests/unit/`
- **Integration Test Location:** `tests/integration/`
- **Coverage Goal:** 80% overall, 85% minimum for unit tests
- **Test Configuration:** `conftest.py` for pytest fixtures
- **Mocking:** unittest.mock + pytest-mock for external dependencies

### Required Test Files for This Story:
- `tests/conftest.py` - Pytest configuration and shared fixtures
- `tests/unit/test_config_loading.py` - Test configuration loading
- `tests/unit/test_logging_setup.py` - Test logging configuration
- Basic test structure validation

### Test Requirements:
- Follow AAA pattern (Arrange, Act, Assert)
- Mock all external dependencies
- Cover edge cases and error conditions
- Generate tests for all public methods
