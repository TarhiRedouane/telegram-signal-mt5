### Rate Limiting & API Management
**Rate Limiting Strategy:**
- **Limit:** 100 requests/minute (1.67 requests/second average)
- **Burst Handling:** Allow burst up to 10 requests, then throttle
- **Backoff Strategy:** Exponential backoff starting at 1 second, max 60 seconds
- **Circuit Breaker:** Open circuit after 5 consecutive failures, half-open after 60 seconds
- **Monitoring:** Track requests/minute, success rate, average latency, cost per request

### Response Caching Strategy
**Cache Implementation:**
- **Key Generation:** SHA256 hash of normalized message text (lowercase, whitespace normalized)
- **Storage:** In-memory cache with SQLite persistence for restart recovery
- **TTL:** 24 hours for signal parsing responses
- **Size Limits:** Maximum 1000 cached responses, LRU eviction
- **Cache Invalidation:** Automatic cleanup of expired entries every hour

### Refactoring Performed

- **File**: `config/openai_config.py`
  - **Change**: Fixed OpenAI model configuration to handle both GPT-5 and legacy models
  - **Why**: GPT-5 models use `max_completion_tokens` instead of `max_tokens` parameter
  - **How**: Added conditional logic to use correct parameter based on model type, preventing API errors

- **File**: `src/signal_parser/llm_parser.py` 
  - **Change**: Moved circuit breaker decorator from parse_with_llm to _make_openai_request
  - **Why**: Circuit breaker should protect the actual API call, not the entire parsing logic
  - **How**: Applied decorator to the method that makes external API calls for better fault isolation

- **File**: `tests/unit/test_llm_parser.py`
  - **Change**: Fixed async test fixtures and mocking patterns
  - **Why**: Tests were failing due to incorrect async/await patterns in mocks
  - **How**: Used AsyncMock for all async operations and added pytest_asyncio fixture decorator
