# Story 20.13: Only the Short "Sell Gold Now" Form Opens a Price-less Setup - Brownfield Bug Fix

## Status
Draft

Source: architecture review fourth pass, finding **F44 (M)**, [review-2026-10.md](../architecture/review-2026-10.md) section 7.2. Roadmap step 20, before 19.2.
Narrows the opener rule of story 20.10 (rule 1).

## Story
**As a** trader whose channels also post results and commentary that name the side and the symbol,
**I want** only a short order such as "sell gold now" or "je vends gold maintenant" to start a price-less setup,
**so that** a post like "Gold sell setup closed in profit" never replaces my open trade's setup, never re-opens a filled setup, and never starts a phantom setup that the next bare number turns into a trade.

## What happens today (code trace at `30cd120`, reproduced 2026-10-15)

`priceless_opener` (setup_aggregator.py:122-133) accepts any text with exactly one side word, an enabled symbol as a whole word and no 4-digit price, unless a negation
comes before the side word or a hyphen follows it. Checked with the real function, all of these return an opener:

| Text | Opener |
|---|---|
| `TP1 HIT SELL GOLD +130 PIPS ✅` | SELL GOLD |
| `Gold sell setup closed in profit` | SELL GOLD |
| `XAUUSD sell running +50 pips` | SELL XAUUSD |
| `gold buy closed BE` | BUY GOLD |
| `Gold SL hit on sell` | SELL GOLD |
| `Les vendeurs de gold sont forts` | SELL GOLD |
| `on attend pour vendre gold` | SELL GOLD |
| `Attention gold, je pense sell plus tard` | SELL GOLD |

The router acts on an opener before every other setup rule and before the correlation engine (main.py:344-354):
- **Opposite side to the chat's setup** → `_start_awaiting_entry` (655-688) replaces it (D5). Its open legs keep their MT5 SL/TP but lose break-even at TP1 and
  the candle-close invalidation. Reproduced: filled BUY setup, then `Gold sell setup closed in profit` → the chat's setup is a new SELL awaiting entry.
- **Same side, filled, not armed** → `_reopen_awaiting_entry` (690-700) re-opens it (D4). A result post right after a fill is exactly this case; a bare number within
  5 min then opens a new trade.
- **No setup, no zone** → a phantom await-entry setup for 5 min; a bare number in that window opens a trade.

Before 20.10 these posts had no effect on setups. Today's channel writes results without the symbol (`TP1 HIT SELL +130 PIPS +2.6R`), so this has not fired yet.

  (test_setup_aggregator.py:546-576).

**Facts that shape the design:**
- **Only the detector changes.** The router branch, D4 and D5 stay as built in 20.10; they just see far fewer messages.
- **Every opener in 20.10 rule 1 is short:** `sell gold now`, `SELL GOLD NOW`, `je vends gold maintenant`, `buy xauusd now`, `sell gold`. A whole-message match keeps them all.
- **A message that is no longer an opener takes the pre-20.10 path:** with a pending setup it goes to `_handle_setup_followup` (no price, no "now" → nothing; an empty
  follow-up can still reach the LLM, as before 20.10); without one it goes to correlation and the parsers (no price → no trade).

## Rules (the behaviour to build)
1. `priceless_opener(text)` returns `(side, symbol)` only when the **whole message**, after trimming spaces, punctuation and emoji at both ends, is:
   optional `je`, then the side word and the symbol in either order (`sell gold`, `gold sell`), then optionally `now` / `maintenant`.
   Side words and symbol aliases are the existing ones (`_BUY_WORD` / `_SELL_WORD`, enabled aliases); case-insensitive; one or more spaces between words.
2. Anything else returns `None`: extra words, a price, a negation, `sell-off`, both sides, a symbol that is not enabled.
3. Unchanged: router branch and its order, D4 (same-side opener after a fill waits for its entry), D5 (opposite opener replaces the setup), bare-price entry, band rule.

## Decisions
- **D5 unchanged in this story.** For a setup that owns open legs, the user replaced D5 on 2026-10-15 with the reversal rule of
  [story 20.14](20.14.story.md) (refused under 300 pips from the open entry; at 300 pips or more a half-risk counter-trade, open trade kept under management).
  This story only narrows which messages count as an opener; 20.14 changes what an opposite opener does.

## Technical Notes
- Why a whole-message match and not more negative patterns: commentary has unbounded phrasing; the order form is short and fixed. A list of excluded words would keep
  leaking.
- Why emoji and punctuation are trimmed: channels add `🔥`, `!!`, `⚠️` to orders. `\W` covers them in Python `re` (emoji are not word characters).
- Out of scope: F45 (SL/TP direction check while a re-opened setup waits for its entry); F46 (second bare number re-targets the entry, by design in 20.10);
  longer orders such as `sell gold now guys` or `sell gold now, entry soon` (rejected by this rule; add a word list later only if the channel uses them).

## Risk and Compatibility Check
- **Primary risk:** a real order with extra words (`sell gold now guys`) no longer opens a setup, so that trade is missed. Mitigation: AC 1 covers the forms seen so far;
  the live log line "Message received … text=…" shows any missed form for a follow-up.
- **Rollback:** `git revert` the story commit. No DB, setting or prompt change.
