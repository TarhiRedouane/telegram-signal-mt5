## Story
**As a** trader running the signal bot,
**I want** break-even and an invalidation close to keep being attempted until MT5 accepts them,
**so that** a transient MT5 failure at the moment TP1 fills does not leave the remaining legs at their original stop loss.

- Follows pattern: "every order/modify goes through the circuit breaker" (`@circuit_breaker` on `modify_position_levels` and `close_position_full`), and

- Touch points: `main.py` (the two methods above), `setup_aggregator.py` (`PendingSetup` gets `be_pending`, `close_pending`).
  No change to `position_manager.py`, MT5 calls, scoring or the database schema.

**The bug (from the code, 2026-10-12):**
1. `_track_setup_legs` (main.py:1192-1199): when TP1 is hit, it sets `be_done = True` **before** the break-even modify runs,
   then calls `_apply_position_levels(position, open_price, None)` for each open leg and ignores the result. `_apply_position_levels`
   returns False on failure (main.py:570-575) and logs a warning. Next poll: `be_done` is True, so the branch never runs again.
   The legs stay at their original SL.
2. `_check_close_invalidation` (main.py:1091-1097): for each open leg calls `close_position_full`; a failed close is logged at info level,
   then the setup is dropped anyway (`_setup_aggregator.drop`, main.py:1097). No second attempt. The protective SL is the only exit.
3. The watcher's idle branch (main.py:1040-1052) can drop a setup with `be_done` False while legs are open and waiting for break-even. A retry
   flag must also stop that drop.

**Measured facts that shape the design:**
- `position_manager.py:259` treats any retcode other than `TRADE_RETCODE_DONE` as failure. When the SL is already at the requested level
  MT5 answers `TRADE_RETCODE_NO_CHANGES` (10025, already mapped in `_get_retcode_description` at line 797). A naive retry would loop forever on that case.
- `close_position_full` on a leg that is already closed returns "Position … not found or already closed" (position_manager.py:955),
  a failure. Retries must skip legs that are no longer open.
- Retries run at the watcher poll (`settings.setup_price_poll_seconds`, default 5 s). The modify call already has its own retry (3 attempts,
  1 s, 2 s backoff) and circuit breaker (opens after 3 failures, 30 s). Stacked retries are acceptable for this story but are noted in Technical Notes.

## Acceptance Criteria

**Functional Requirements:**
1. Break-even is considered **applied** only when every leg that was open at TP1 has a successful SL modify. Until then the setup stays
   in a `be_pending` state; `be_done` is set only on full success.
2. While `be_pending` is True, each watcher poll retries the break-even modify for the legs that are still open (`get_close_reason` is None).
   Legs already closed are skipped, not retried.
3. Unfilled legs are still disarmed **immediately** at TP1 (as today, main.py:1194), so a retry never opens a new entry. `be_pending` does not re-arm anything.
4. The idle-timeout branch (main.py:1040-1052) does not drop a setup while `be_pending` is True.
5. A break-even modify that MT5 answers with `TRADE_RETCODE_NO_CHANGES` counts as applied (the SL already is at the target).
6. The invalidation close is considered complete only when every leg that was open is closed (or already closed). If any close fails, the setup is kept
   with `close_pending` True and retried on the next poll. The setup is dropped only when no leg is open.
7. Each failed attempt logs a warning with the ticket and the MT5 error. After 10 consecutive failures for the same ticket, log at ERROR level once
   (`"still not at break-even after N attempts, ticket …"`), and keep retrying. Alerts are not wired yet (roadmap step 4).
8. Any code that checks `be_done` to mean "break-even is in force" (main.py:846 zone early-leg check, main.py:910 SL lock in `_apply_setup_levels`)
   treats `be_pending` the same way: no new legs after TP1, and a later SL may not loosen the lock while break-even is pending.

**Integration Requirements:**
9. No change to scoring, thresholds, `setup_price_poll_seconds`, `setup_max_lifetime_seconds` or the position manager's retry settings.
10. Happy path unchanged: TP1 hit with all modifies succeeding gives the same log decisions and the same MT5 calls as today (verified by the
    existing test `test_main_ladder_fills_legs_progressively_then_tp1_moves_rest_to_break_even`, unchanged).
11. Complete single-message signals and the zone/setup paths otherwise unaffected; full `pytest` stays green (704 passed, 6 skipped before this story).

**Quality Requirements:**
12. New tests fail on the code before the change (record in Dev Agent Record). Required cases in Task 1.
13. `black --check`, `ruff check` clean on touched files; `mypy src/` gives no new errors: baseline today is **227 errors in 33 files** (checked 50 source files). Record the count before and after.
14. Dev Agent Record lists: tests added, failing-before / passing-after output, full pytest result.

## Technical Notes
- **Why a separate `be_pending` and not "retry `be_done`":** `be_done` also gates the zone early-leg check and the SL lock. Setting it early was
  the bug. Keeping the leg disarm separate from break-even keeps unfilled legs from firing during the retry window.
- **Retry layers:** `modify_position_levels` already retries 3 times inside one call (1 s, 2 s backoff) and is circuit-broken. The new retry is one
  more layer at poll rate. Together a stuck MT5 gets tried often. That is intended for a stop-loss move on open risk, but log volume matters:
  AC7 limits ERROR logs to once per ticket.
- **Circuit breaker interaction:** after 3 failures the breaker opens for 30 s and calls fail fast with "Circuit breaker is OPEN for <function>" (`utils/circuit_breaker.py:75`).
  That is a failure, so the retry continues after the breaker recovers. Do not special-case it.
- **Positions already closed while pending:** `get_close_reason` returns "tp"/"sl"/"other" for them; they are skipped. A leg closed by SL during the
  retry window is not a break-even failure.
- **Open price used as break-even level:** `open_price` is the mid price, not the fill (review F22). That is a separate story (20.4). This story keeps
  `open_price` as the target.
- **Out of scope:** storing pending state across restarts (roadmap step 3); alerts (step 4); fill-price fix (20.4); MT5 startup (20.5); PID
  check (20.6); removing the retry decorator on order sends (F14, story 19.9).
- **Key constraints:** high-risk code rule (CLAUDE.md): narrow change, log every decision. No change to MT5 calls themselves.

## Risk and Compatibility Check
- **Primary risk:** a retry keeps modifying a position that a human has already moved or closed in the terminal, and overrides it.
  Mitigation: AC2 retries only legs still open and only the break-even level. A manual move to a different SL is overwritten once per poll
  until break-even is applied; this is the intended trade-off and is logged.
- **Secondary risk:** a stuck pending state keeps a setup in memory forever. Mitigation: the existing `setup_max_lifetime_seconds` branch
  (main.py:1025-1029) still drops the setup; AC4 only blocks the idle drop.
- **Rollback:** `git revert` the story commit. The new fields are in-memory only; no database or config change.

### Refactoring Performed
- **File**: `main.py` (`_apply_setup_levels`)
  - **Change**: when a profit-locking SL from the author is applied to a leg while break-even is pending, that leg's `("be", ticket)` retry key
    is removed.
  - **Why**: without it the next break-even retry moved the SL **back to the entry price**, loosening the author's tighter stop. Reproduced:
    SELL legs opened at 4192/4193, break-even fails on leg 2, author posts "SL 4185" → applied → next poll retried leg 2 to 4192.
    `_apply_setup_levels` already guarantees that, after TP1, only a profit-locking SL gets through (`locks_profit`), so a leg that received one
    is at or beyond break-even.
  - **How**: the retry no longer overrides the better stop; break-even completes once no leg needs it. Also simplified the call site
    (`continue` when there is nothing to send, then one `applied` check) instead of a nested conditional.
- **File**: `tests/unit/test_break_even_retry.py`
  - **Change**: new test `test_profit_locking_sl_during_pending_break_even_is_not_undone_by_retry`.
  - **Why/How**: fails on the dev version of `main.py` (5th modify call = retry back to 4192), passes with the fix.
