### MT5 Connection Architecture
**Source:** [Source: architecture/components.md#mt5-executor-component]
**Required MT5 Connection Interfaces:**
- `connect_mt5(login: str, password: str, server: str)` - Initialize connection with credentials
- `get_terminal_info() -> TerminalInfo` - Retrieve terminal and broker information
- `get_account_info() -> AccountInfo` - Get account details and trading permissions
- `validate_symbol(symbol: str) -> SymbolSpec` - Check symbol availability and specifications
- `check_connection() -> ConnectionHealth` - Health check for connection monitoring

**Integration Requirements:** Connection pool pattern with maximum 5 concurrent connections, automatic reconnection on disconnect, circuit breaker for cascade failure prevention, structured logging for all operations.

### MT5 Configuration Management
**Source:** [Source: architecture/tech-stack.md, architecture/source-tree.md]
**Environment Variables Required:**
- `MT5_LOGIN` - MT5 account login number (integer)
- `MT5_PASSWORD` - MT5 account password (encrypted storage recommended)
- `MT5_SERVER` - MT5 broker server name (e.g., "MetaQuotes-Demo")
- `MT5_PATH` - Optional MT5 installation path for custom installations
- `MT5_TIMEOUT_SECONDS` - Connection timeout (default: 60)
- `MT5_MAX_CONNECTIONS` - Connection pool size (default: 5)
- `MT5_RECONNECT_DELAY` - Base delay for reconnection attempts in seconds (default: 5)

**Configuration Class Integration:** Extend `config/settings.py` with MT5Settings class using Pydantic validation for credentials, timeout values, and connection parameters.

### Coding Standards Requirements
**Source:** [Source: architecture/coding-standards.md]
**Critical Rules for This Story:**
- **All external API calls must use circuit breaker decorator:** MT5 connection calls must use `@circuit_breaker` from decorators.py
- **Never use print() for output - use logger:** All MT5 connection output must use structured logging system
- **Never log sensitive data:** Hash MT5 credentials in logs, never log passwords or account details
- **All async functions must handle cancellation:** MT5 operations must cleanup on task cancel
- **Database operations must use repository pattern:** Connection state persistence via repository class

### Connection Pool and Health Management
**Connection Pool Design:**
- **Pool Size:** Maximum 5 concurrent connections to prevent MT5 resource exhaustion
- **Connection Lifecycle:** Initialize on startup, validate every 30 seconds, reconnect on failure
- **Health Checks:** Ping MT5 server, verify account status, check symbol availability
- **Failover Strategy:** Circuit breaker after 3 consecutive failures, exponential backoff (5s, 10s, 20s, max 60s)

### Error Handling Patterns
**Source:** [Source: architecture/error-handling-strategy.md, architecture/coding-standards.md]
**MT5-Specific Error Scenarios:**
- **Invalid Credentials:** Clear error message with account validation guidance
- **Terminal Not Running:** Detect MT5.exe process, provide installation/startup instructions
- **Network Issues:** Retry with exponential backoff, switch to offline mode if persistent
- **Trading Disabled:** Check account permissions and provide specific error details
- **Symbol Unavailable:** Fallback to alternative symbol names, notify user of broker limitations
